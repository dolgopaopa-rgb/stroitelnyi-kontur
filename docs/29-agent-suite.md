# Совет агентов проверки сайта

Дата: 2026-06-16.

Этот документ описывает расширенный набор проверяющих агентов для "Строительного контура". Агентский набор ничего не меняет в коде и базе. Его задача - после каждой заметной правки проверить, что сайт живой, основные сценарии не сломаны, роли не расползлись, мобильная версия остается рабочей, а критичные пользовательские процессы не потеряли смысл.

## Где лежит запуск

```text
tools/kontur_agent_suite.py
```

GitHub Actions запускает его через:

```text
.github/workflows/quality-agent.yml
```

Старый строгий агент `tools/kontur_quality_agent.py` не удален. Он теперь запускается внутри общего набора как "Основной QA-агент".

## Какие агенты входят в набор

1. **Доступность сайта** - проверяет `/health`, `/login` и главную точку входа.
2. **Сборка и синтаксис** - проверяет Python и JavaScript на синтаксические ошибки.
3. **Статика и PWA** - проверяет CSS/JS, manifest, service worker, иконки и синхронизацию версии кэша.
4. **Мобильность** - смотрит, есть ли pull-to-refresh, поддержка прокрутки, совместимый bundle для старых WebView/Huawei, удобный мобильный вход.
5. **Роли и доступы** - контролирует матрицу меню, режим ИИ-аудитора, фильтрацию документов и ограничения менеджера.
6. **Безопасность** - следит, чтобы в Git не попали `.env`, ключи, рабочие базы, и проверяет базовые флаги сессии.
7. **Документы и файлы** - проверяет папки базы знаний, drag-and-drop, HEAD/Range для файлов и заготовку облачного хранилища.
8. **MAX и уведомления** - проверяет UTF-8/base64 отправку сообщений, персональные уведомления и защиту от испорченной кириллицы.
9. **Строительная логика** - контролирует наличие сущностей: объекты, задачи, материалы, работы, сметы, допработы, замечания, фотоотчеты, договоры.
10. **UX и дизайн** - ищет человеческие статусы, экран "Сегодня", сворачиваемые блоки, индикатор загрузки и отсутствие технических enum в видимом HTML.
11. **API smoke** - при наличии логина и пароля проверяет основные JSON API.
12. **Основной QA-агент** - запускает уже существующую глубокую проверку проекта.

## Как запускать локально

Без секретов:

```powershell
python tools\kontur_agent_suite.py --url https://kontur.derevgroup.ru
```

С отчетом в папку:

```powershell
python tools\kontur_agent_suite.py --url https://kontur.derevgroup.ru --report-dir docs\agent-reports
```

Если на машине есть переменные окружения для закрытого доступа:

```powershell
$env:KONTUR_BASIC_USER="..."
$env:KONTUR_BASIC_PASSWORD="..."
python tools\kontur_agent_suite.py --url https://kontur.derevgroup.ru --report-dir docs\agent-reports
```

Пароли и токены в файлы не записывать.

## Как читать отчет

Статусы:

- `OK` - контракт соблюден.
- `WARN` - критичной поломки не найдено, но место требует проверки человеком.
- `FAIL` - критичная проблема, перед приемкой нужно исправить.
- `INFO` - справочная запись, обычно из-за отсутствия локального инструмента или секретов.

Порядок работы:

1. Сначала исправлять все `FAIL`.
2. Потом смотреть `WARN`.
3. Если агент дал рекомендацию, проверять ее по фактическому сценарию в программе.
4. После исправлений снова запускать агентский набор.

## Как это работает в GitHub

Workflow `Quality Agent` запускается:

- после каждого `push`;
- при pull request;
- вручную через `Actions -> Quality Agent -> Run workflow`.

В GitHub Summary будет полный отчет по всем агентам. Если есть `FAIL`, workflow завершится ошибкой.

## Что агент не делает

- не чинит код сам;
- не меняет базу;
- не отправляет сообщения в MAX;
- не показывает секреты;
- не заменяет ручную проверку сложных сценариев коллегами.

Он нужен как постоянная сетка безопасности: быстро подсветить, где после правки могло поехать приложение.

# Агент проверки кнопок и сценариев

Дата: 2026-05-28

## Задача

После каждой правки нужен независимый контроль: приложение должно не только открываться, но и сохранять ключевые пользовательские сценарии. Агент не меняет код сам. Он запускается, фиксирует нарушения и отдает отчет.

## Когда запускается

- автоматически после каждого `push` в GitHub;
- автоматически для каждого `pull_request`;
- вручную через GitHub Actions, если нужно проверить сайт отдельно.

## Что проверяет

- наличие основных кнопок и привязку обработчиков в `app/static/app.js`;
- наличие основных форм и отправку в ожидаемые API;
- сохранение выбранной роли после обновления страницы;
- автосохранение черновика карточки нового объекта и понятные ошибки заполнения;
- ограничения меню для менеджера и прораба;
- запрет менеджеру принимать объект в работу вместо руководителя строительства;
- запрет окончательного удаления объектов всем, кроме гендиректора;
- совпадение версии фронтенда в `index.html` и `sw.js`, чтобы мобильные устройства не брали старый код из кэша;
- доступность production-сайта и API, если в GitHub доступны секреты авторизации.

## Как читать отчет

Отчет появляется в GitHub Actions Summary. Статусы:

- `OK` - проверка пройдена;
- `WARN` - есть риск или неполная проверка, но сайт не считается сломанным;
- `FAIL` - найдено нарушение, правку нельзя считать готовой без разбора.

## Важное ограничение

Агент проверяет контракты и сценарии по коду и доступному сайту. Он не заменяет ручное тестирование коллегами, но должен ловить типовые поломки: кнопка есть, но ничего не делает; форма выглядит сохраненной, но не отправляется; роль сбрасывается; меню показывает лишние разделы.

# Работа с другого компьютера

Этот файл нужен, чтобы продолжать проект с домашнего или рабочего компьютера без потери контекста.

## Главный принцип

Источником правды является GitHub:

```text
https://github.com/dolgopaopa-rgb/stroitelnyi-kontur
```

Все изменения кода, документов, сценариев проверки и проектных решений должны попадать в репозиторий через commit и push. Если работа велась на одном компьютере, на втором компьютере сначала нужно сделать `git pull`.

## Как начать работу на новом компьютере

1. Установить Git.
2. Склонировать проект:

```bash
git clone https://github.com/dolgopaopa-rgb/stroitelnyi-kontur.git
cd stroitelnyi-kontur
```

3. Перед началом каждого рабочего дня подтянуть свежие изменения:

```bash
git pull
```

4. Открыть эти файлы:

- `docs/16-project-worklog.md` - где остановились и что меняли;
- `docs/17-quality-agent.md` - как проверять приложение;
- `docs/15-colleague-test-lists.md` - что просить проверить коллег;
- `docs/12-deployment.md` - как обновлять сервер;
- `docs/13-selectel-server.md` - сведения по текущему VPS.

## Как фиксировать новые изменения

После каждой законченной логической правки:

1. Добавить запись в `docs/16-project-worklog.md`.
2. Указать:
   - что попросили сделать;
   - как поняли задачу;
   - какое решение выбрали;
   - какие файлы изменили;
   - как проверили;
   - что осталось на потом.
3. Сделать commit.
4. Отправить в GitHub:

```bash
git push
```

## Как обновлять постоянный сервер

После push на GitHub сервер обновляется командой:

```bash
ssh root@79.143.30.43
cd /opt/stroitelnyi-kontur
bash deploy/update.sh
```

Рабочая ссылка:

```text
https://kontur.derevgroup.ru
```

## Что нельзя хранить в GitHub

В репозиторий нельзя добавлять:

- пароли;
- токены MAX;
- содержимое `.env`;
- реальные персональные данные сверх того, что уже требуется для тестовой базы;
- резервные копии базы;
- фото, видео и документы объектов, если они содержат рабочую или клиентскую информацию.

Для секретов используются переменные окружения сервера или GitHub Secrets.

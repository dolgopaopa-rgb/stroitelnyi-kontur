# Автоматическая передача сметы из Сметтера

## Назначение

Менеджер указывает в карточке объекта ссылку на конкретную смету в Сметтере. При сохранении Контур читает смету через Public API v2 и автоматически формирует два документа объекта:

- `Задание на работы из Сметтера`;
- `Перечень материалов из Сметтера`.

Интеграция односторонняя: `Сметтер -> Контур`. Контур выполняет только `GET`-запросы и ничего не изменяет в Сметтере.

## Правила данных

- В задание на работы попадают активные позиции типа `labor` с ненулевым количеством.
- В перечень материалов попадают активные позиции типа `material` с ненулевым количеством.
- Группы и этапы сохраняются как структура разделов.
- Доставка, механизмы, отменённые и нулевые позиции не переносятся.
- Цены, себестоимость и маржа в сформированные документы не переносятся.
- Повторное сохранение неизменённой сметы не создаёт дубли.
- При изменении сметы прежние автоматически созданные документы архивируются, а новая версия становится активной.

## Доступы

- Директор и руководитель строительства видят оба документа.
- Прораб видит задание на работы и перечень материалов только по доступному ему объекту.
- Снабженец видит перечень материалов, но не задание на работы.
- Менеджер видит документы в карточке созданного им объекта.

## Ошибки и повторная загрузка

Если ссылка неверна, ключ API недоступен или Сметтер временно не отвечает, карточка сохраняется с явным предупреждением. Объект нельзя передать в строительство, пока актуальная автоматическая загрузка не завершится. Повторное сохранение карточки повторяет безопасный `GET`-запрос. Для аварийного сценария менеджер может явно приложить оба прежних файла вручную; Контур отметит, что использован резервный способ.

## Настройка

Секреты не хранятся в репозитории. Среда запуска должна содержать:

- `SMETTER_COMPANY_ID`;
- `SMETTER_API_TOKEN`;
- `SMETTER_API_TIMEOUT_SECONDS` при необходимости, по умолчанию 30 секунд.

Для staging используются `STAGING_SMETTER_COMPANY_ID` и `STAGING_SMETTER_API_TOKEN`.

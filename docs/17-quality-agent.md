# Агент проверки строительного контура

Этот файл описывает постоянного QA-агента проекта. Его задача - регулярно проверять приложение и оставлять понятные отчеты в репозитории.

## Роль агента

Агент смотрит на продукт сразу с четырех сторон.

**1. Старший программист**

- ищет ошибки, регрессии, поломки API и слабые места архитектуры;
- проверяет, не сломали ли новые изменения старые сценарии;
- обращает внимание на хранение данных, кэш, права доступа, уведомления и безопасность;
- сначала пишет о рисках и багах, потом о косметике.

**2. Веб-дизайнер**

- проверяет плотность интерфейса, читаемость, мобильную версию, размеры карточек и кнопок;
- предлагает дорогой, аккуратный и рабочий визуальный стиль без лишнего декоративного шума;
- следит, чтобы интерфейс был похож на серьезный внутренний инструмент, а не на лендинг;
- предлагает цветовые решения: графит, глубокий зеленый, теплый золотой акцент, спокойные серые фоны, умеренные статусы.

**3. Человек из строительного процесса**

- проверяет, не теряется ли логика стройки: объект, договор, смета, работы, материалы, допработы, акты, снабжение, прораб, технадзор;
- смотрит, кому реально нужна информация, а кому ее показывать нельзя;
- предлагает улучшения процессов только если они помогают избежать путаницы, двойной работы или потери денег.

**4. Контролер пользовательского сценария**

- проверяет, сможет ли сотрудник выполнить задачу без объяснений в чате;
- отмечает места, где нужна подсказка, понятное название или другой порядок действий;
- смотрит, что происходит после нажатия кнопок: есть ли уведомление, меняется ли статус, кто видит результат.

## Что агент проверяет автоматически

Автоматический скрипт лежит здесь:

```text
tools/kontur_quality_agent.py
```

Он проверяет:

- доступность сайта;
- включена ли защита логином;
- отдаются ли главные статические файлы;
- не устарел ли PWA-кэш;
- есть ли в текущем фронтенде важные исправления;
- доступны ли ключевые API, если переданы логин и пароль;
- формирует Markdown-отчет.

GitHub Actions workflow:

```text
.github/workflows/quality-agent.yml
```

Он запускается вручную и по расписанию, создает отчет в `docs/qa-reports/` и коммитит его в историю репозитория.

## GitHub Secrets для глубокой проверки

Чтобы агент мог проверять защищенный сайт, в настройках GitHub нужно добавить секреты:

```text
KONTUR_BASIC_USER
KONTUR_BASIC_PASSWORD
```

Без этих секретов агент увидит только, что сайт закрыт авторизацией, но не сможет проверить API и внутренние страницы.

## Формат отчета

Отчет должен содержать:

- дату и адрес проверки;
- краткую сводку;
- список проверок со статусами `OK`, `WARN`, `FAIL`, `INFO`;
- инженерные замечания;
- дизайнерские предложения;
- замечания по строительной логике;
- рекомендуемые следующие действия.

## Как запускать вручную

Локально:

```bash
python tools/kontur_quality_agent.py --url https://kontur.derevgroup.ru --report-dir docs/qa-reports
```

С логином и паролем через переменные окружения:

```bash
KONTUR_BASIC_USER=... KONTUR_BASIC_PASSWORD=... python tools/kontur_quality_agent.py --url https://kontur.derevgroup.ru --report-dir docs/qa-reports
```

На Windows PowerShell:

```powershell
$env:KONTUR_BASIC_USER="..."
$env:KONTUR_BASIC_PASSWORD="..."
python tools/kontur_quality_agent.py --url https://kontur.derevgroup.ru --report-dir docs/qa-reports
```

## Как использовать вывод агента

1. Сначала исправлять `FAIL`.
2. Потом разбирать `WARN`.
3. Дизайнерские предложения вносить в план, если они улучшают работу людей.
4. Строительные предложения обсуждать с руководителем строительства, прорабами, снабжением и технадзором.
5. После внесения изменений добавить запись в `docs/16-project-worklog.md`.

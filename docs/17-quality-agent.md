# Агент проверки строительного контура

## Актуальный основной запуск

С 2026-06-16 основной способ проверки проекта - расширенный набор агентов:

```powershell
python tools\kontur_agent_suite.py --url https://kontur.derevgroup.ru
```

Он запускает несколько независимых проверок: доступность сайта, сборку, PWA, мобильную совместимость, роли, безопасность, документы, MAX-уведомления, строительную логику, UX и API smoke. Старый агент `tools/kontur_quality_agent.py` остается внутри этого набора как "Основной QA-агент".

Подробности: [Совет агентов проверки сайта](29-agent-suite.md).

Этот файл описывает постоянного QA-агента проекта. Его задача - проверять приложение после изменений и показывать понятный отчет в GitHub Actions.

## Роль агента

Агент смотрит на продукт сразу с четырех сторон.

**1. Старший программист**

- ищет ошибки, регрессии, поломки API и слабые места архитектуры;
- проверяет, не сломали ли новые изменения старые сценарии;
- обращает внимание на хранение данных, кэш, права доступа, уведомления и безопасность;
- сначала пишет о рисках и багах, потом о косметике.

**2. Веб-дизайнер**

- проверяет плотность интерфейса, читаемость, мобильную версию, размеры карточек и кнопок;
- предлагает дорогой, аккуратный и рабочий визуальный стиль без лишнего декоративного шума;
- следит, чтобы интерфейс был похож на серьезный внутренний инструмент, а не на лендинг;
- предлагает цветовые решения: графит, глубокий зеленый, теплый золотой акцент, спокойные серые фоны, умеренные статусы.

**3. Человек из строительного процесса**

- проверяет, не теряется ли логика стройки: объект, договор, смета, работы, материалы, допработы, акты, снабжение, прораб, технадзор;
- смотрит, кому реально нужна информация, а кому ее показывать нельзя;
- предлагает улучшения процессов только если они помогают избежать путаницы, двойной работы или потери денег.

**4. Контролер пользовательского сценария**

- проверяет, сможет ли сотрудник выполнить задачу без объяснений в чате;
- отмечает места, где нужна подсказка, понятное название или другой порядок действий;
- смотрит, что происходит после нажатия кнопок: есть ли уведомление, меняется ли статус, кто видит результат.

## Что агент проверяет автоматически

Автоматический скрипт лежит здесь:

```text
tools/kontur_quality_agent.py
```

Он проверяет:

- доступность сайта;
- включена ли защита логином;
- отдаются ли главные статические файлы;
- не устарел ли PWA-кэш;
- совпадает ли версия фронтенда в репозитории и на production;
- есть ли в текущем фронтенде важные исправления;
- есть ли на рабочем столе блок контрольных сигналов;
- доступны ли ключевые API, если переданы логин и пароль;
- есть ли просроченные задачи, задачи к приемке, проблемные заявки материалов, сверхбюджет без решения, неполные назначения по объектам и непривязанные MAX-уведомления;
- формирует Markdown-отчет.

GitHub Actions workflow:

```text
.github/workflows/quality-agent.yml
```

Он запускается:

- автоматически после каждого `push` в ветку `main`;
- вручную через вкладку GitHub Actions.

Агент ничего не меняет в репозитории, не делает commit и не исправляет код сам. Его задача - проверить и показать отчет в логе запуска и в `Step summary`.

## GitHub Secrets для глубокой проверки

Чтобы агент мог проверять защищенный сайт, в настройках GitHub Actions должны быть секреты:

```text
KONTUR_BASIC_USER
KONTUR_BASIC_PASSWORD
```

Без этих секретов агент увидит только, что сайт закрыт авторизацией, но не сможет проверить API и внутренние страницы.

На 2026-05-21 эти секреты уже добавлены в репозиторий через GitHub Actions Secrets. Их значения не хранятся в коде и не отображаются в истории.

## Формат отчета

Отчет в GitHub Actions содержит:

- дату и адрес проверки;
- краткую сводку;
- список проверок со статусами `OK`, `WARN`, `FAIL`, `INFO`;
- инженерные замечания;
- дизайнерские предложения;
- замечания по строительной логике;
- рекомендуемые следующие действия.

## Как запускать вручную в GitHub

1. Открыть репозиторий `stroitelnyi-kontur`.
2. Перейти во вкладку `Actions`.
3. Выбрать `Quality Agent`.
4. Нажать `Run workflow`.
5. Открыть завершенный запуск и посмотреть `Summary` или лог шага `Run quality agent`.

## Как запускать локально

Локально:

```bash
python tools/kontur_quality_agent.py --url https://kontur.derevgroup.ru
```

С логином и паролем через переменные окружения:

```bash
KONTUR_BASIC_USER=... KONTUR_BASIC_PASSWORD=... python tools/kontur_quality_agent.py --url https://kontur.derevgroup.ru
```

На Windows PowerShell:

```powershell
$env:KONTUR_BASIC_USER="..."
$env:KONTUR_BASIC_PASSWORD="..."
python tools/kontur_quality_agent.py --url https://kontur.derevgroup.ru
```

## Как использовать вывод агента

1. Сначала исправлять `FAIL`.
2. Потом разбирать `WARN`.
3. Рекомендации `HIGH` разбирать до следующего цикла доработок.
4. Дизайнерские предложения вносить в план, если они улучшают работу людей.
5. Строительные предложения обсуждать с руководителем строительства, прорабами, снабжением и технадзором.
6. После внесения изменений добавить запись в `docs/16-project-worklog.md`.
